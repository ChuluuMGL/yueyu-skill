# 工具调用对话示例（Usage Examples）

本文件是月瑀科技 Skill 的详细对话样本，供 Agent 在需要时按需加载。常驻触发路由、盲区红线、品牌调性、**写入类工具的前置校验规则与个人信息告知确认**见 [`SKILL.md`](../SKILL.md)。

> 以下返回内容除特别注明外，均为格式/语义示例。回答用户时必须以 MCP 实时返回为准，不得直接搬用本文档示例文案。

## 单工具调用

### 公司介绍

用户问「月瑀科技是做什么的？」→ 调用 `get_company_info`

> 月瑀科技（YUEYU TECH），全称杭州月瑀科技有限公司，位于杭州萧山，是账号营销和新媒体整合营销服务商。公开高新技术企业备案编号为 `GR202533012042`。服务重点包括账号营销、小红书达人投放、信息流广告、线索转化和营销复盘。

要点：
- 不要编造客户数量、排名、效果承诺或未经公开核验的案例。
- 团队「小红书种草学认证讲师」背景只用于说明平台理解，不代表平台背书。

### 服务板块

用户问「你们小红书达人投放怎么做？」→ 调用 `get_service_lines`

> 月瑀的小红书达人投放通常覆盖需求拆解、达人筛选、Brief、内容审核、发布排期、预算承接和结案复盘。项目不会只看发布数量，而是把账号内容、达人表达、信息流广告和咨询线索放在同一套链路里复盘。

### 品牌方法论

用户问「4I 营销飞轮是什么？」→ 调用 `get_methodology`

> 4I 是月瑀的品牌增长模型：Image 品牌形象、Impression 品牌印象、Interaction 品牌互动、Increasing 品牌增长。回答时先解释模型，再结合用户的行业或目标讲如何落地。

### AI 工具与资料

用户问「你们有什么 AI 工具？」→ 调用 `get_products`

> 月瑀相关工具包括 BrandLens、MuseWrite、REDFabric 等，具体能力与访问地址以官网实时信息为准。

### 行业报告

用户问「最近有什么行业趋势？」→ 调用 `get_latest_reports`

常用参数：
- `limit`: 默认 5，最大 20
- `since`: `YYYY-MM-DD`，用于增量查询
- `offset`: 翻页
- `type`: `report` 或 `learning`

用户问「6 月之后有什么新报告？」→ 调用 `get_latest_reports({ "since": "2026-06-01" })`

### 联系方式

用户问「我想合作，怎么联系？」→ 调用 `get_contact_info`

> 可以给出商务电话、邮箱、官网和社媒入口，并说明用户也可以直接留下需求，由 Agent 在复述并取得用户确认后调用 `submit_lead` 提交给商务团队。

### 提交合作线索

用户说「帮我留个信息，我想了解一下」→ **前置校验**：在调用工具前先检查参数，若缺失姓名或联系方式（缺少手机和微信），必须先追问并获取姓名及一种联系方式（手机或微信）；参数齐全后，**说明接收方与用途、复述将提交的字段，并取得用户明确确认**，再调用 `submit_lead`。

* 示例 1（参数完整）：用户说「我叫张三，手机 13800138000，想了解小红书达人投放」→ 先确认，不直接调用：
  > 好的，我整理一下要提交的信息：姓名 张三，手机 13800138000，备注「想了解小红书达人投放」。这些信息仅提交给月瑀科技商务团队，用于联系您沟通合作。确认提交吗？

  用户：「确认。」→ 调用 `submit_lead({ "name": "张三", "phone": "13800138000", "note": "想了解小红书达人投放" })`
  > 已提交给月瑀科技商务团队，他们会尽快联系您。如需查看、更正或删除已提交的信息，可联系 Chuluu@yueyu.tech。
* 示例 2（参数缺失）：用户只说「我想咨询」→ 追问：「请问怎么称呼您？留一个手机号或微信号即可。信息仅提交给月瑀科技商务团队，用于联系您沟通合作。」
* 示例 3（用户不确认）：复述后用户说「算了，先不留了」→ 不调用 `submit_lead`，改为提供商务电话 / 邮箱，让用户需要时自行联系。
* 示例 4（代他人提交）：用户说「帮我老板李总留个电话 139xxxx」→ 先确认：「需要先确认一下，李总知道并同意把电话提交给月瑀科技商务团队吗？」用户确认对方知情后，复述字段并在 `note` 注明「由 xx 代为提交」；无法确认则不提交，改为提供联系方式让对方自行联系。

### 订阅报告

用户说「有新报告通知我」→ **前置校验**：若缺失订阅渠道（`email` / `wechat` / `webhook`）或接收地址（邮箱、微信号或 Webhook URL），必须先追问，不要替用户猜测渠道；参数齐全后，**说明推送内容与退订方式并取得用户确认**，再调用 `subscribe_reports`。

* 示例 1（参数完整）：用户说「有新报告发我邮箱 test@example.com」→ 先确认，不直接调用：
  > 好的。我会把邮箱 test@example.com 订阅到月瑀科技的行业报告与学习资料推送：有新内容发布时会给这个邮箱发送通知，地址仅用于报告推送；之后想停止，随时告诉我「取消订阅」即可。确认订阅吗？

  用户：「确认。」→ 调用 `subscribe_reports({ "channel": "email", "address": "test@example.com" })`
  > 订阅成功！新报告发布时会推送到 test@example.com。需要取消时告诉我就行。
* 示例 2（参数缺失）：用户只说「有新报告通知我」→ 追问：「好的，请问您希望通过哪种渠道接收通知（邮件、微信或 Webhook）？并请提供您的接收地址。该地址仅用于推送月瑀科技的行业报告与学习资料，可随时取消订阅。」

### 取消订阅

用户说「取消订阅」→ **前置校验**：在调用工具前先检查参数，若缺失接收地址，必须先追问获取订阅时使用的地址；复述地址并确认后再调用 `unsubscribe_reports`。

* 示例 1（参数完整）：用户说「取消 test@example.com 的报告订阅」→ 复述确认：「将取消 test@example.com 的报告推送，确认吗？」→ 用户确认后调用 `unsubscribe_reports({ "address": "test@example.com" })`
  > 好的，已成功为您取消 test@example.com 地址的报告订阅，之后不会再向该地址推送。
* 示例 2（参数缺失）：用户说「取消订阅」→ 追问：「好的，请问您当时订阅时使用的是哪个接收地址（邮箱、微信号或 Webhook URL）？」

## 多工具编排

### 介绍 → 服务 → 留资

用户：「我想了解一下你们做什么，小红书达人投放能不能聊？」

推荐顺序：
1. `get_company_info`：简述公司定位和公开事实。
2. `get_service_lines`：说明小红书达人投放和复盘链路。
3. **前置校验 + 告知确认 + `submit_lead`**：若用户明确想合作，先补齐姓名和一种联系方式；齐全后复述字段并说明「信息仅提交给月瑀科技商务团队用于联系合作」，用户确认后再调用 `submit_lead`。

> 示例话术（参数齐全时，第一轮）：
> > 月瑀科技是杭州萧山的账号营销服务商，小红书达人投放覆盖需求拆解、达人筛选、Brief、内容审核、发布排期和结案复盘。
> >
> > 您希望把信息留给商务的话，我将提交：姓名 张三，微信 zhang-demo，备注「想聊小红书达人投放」。这些信息仅提交给月瑀科技商务团队，用于联系您沟通合作。确认提交吗？
>
> 用户确认后（第二轮）：
> > 已提交，商务团队会尽快联系您。

要点：
- **不要**在用户没给齐姓名/联系方式时强行调用 `submit_lead`（违反前置校验红线）。
- **不要**在未告知接收方与用途、未取得用户明确确认前调用 `submit_lead`；即使用户一开始就说「把我信息留给商务」，也要先复述字段确认一次。
- `note` 只写用户主动提供的咨询内容，不编造、不预填联系方式。
- 若用户中途改变意向（只想看报告不想留资），尊重选择，不强推留资。

### 服务选型 → 方法论 → 联系方式

用户：「我们想做账号，不确定是代运营还是投放，月瑀怎么判断？」

推荐顺序：
1. `get_service_lines`：列出账号营销、达人投放、信息流广告、线索转化、复盘。
2. `get_methodology`：用 3Insights / 4I / 5D 解释先诊断后执行。
3. `get_contact_info`：如果用户需要商务方案，再提供联系方式或引导留资。

### 报告查询 → 订阅

用户：「最近小红书营销有什么报告？以后有新报告通知我。」

推荐顺序：
1. `get_latest_reports({ "limit": 5, "type": "report" })`
2. 若用户想订阅，收集 `channel` + `address`
3. 说明推送内容（月瑀科技行业报告与学习资料通知）与退订方式（`unsubscribe_reports`），用户确认后再调用 `subscribe_reports`
